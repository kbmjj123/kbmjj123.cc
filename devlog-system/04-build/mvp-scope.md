# 04 · MVP 边界：第一版做什么

> 原则：**第一版只做核心 70%**，跑通后再根据实际使用调整。
> 复杂度可控，CodeBuddy 一次能写完，当天就能用。

---

## 一、做 / 不做清单

### ✅ 第一版做

| 功能 | 说明 |
|---|---|
| 信号检测 | 五类信号 + 细节判定 + ignore 优先级 |
| 日志追加 | 固定格式追到 `.dev-log/log.md` |
| 项目配置读取 | 读取 `.dev-log/config.md`，合并 tags/focus/ignore |
| 截图提醒 | 分级 + 每日上限 + 同一问题不重复 |
| 脱敏过滤 | 密钥、连接串、业务数据 |
| 孤儿素材列出 | 聚合时列出待认领素材 |
| 聚合生成草稿 | 按标签分组 → 输出到 `drafts/` |

### ❌ 第一版不做

| 功能 | 原因 |
|---|---|
| 跨项目自动聚合 | 先手动指定路径，跑通再说 |
| 孤儿素材自动归类 | 先列出来手动认领 |
| 自动生成 L1 碎片 | 先把素材池攒起来 |
| 截图自动重命名 | 后续脚本批量处理即可 |
| 日志自动归档 | 超过 50 条再考虑 |
| 自动发布 | 永远人工过目 |
| 全局项目清单自动扫描 | 第一版手动指定 |

## 二、第一版的三个简化决策

| 项 | 简化做法 | 后续可升级 |
|---|---|---|
| 触发方式 | 每次回答结束检查 | 可加手动标记模式 |
| 判断权 | Skill 自己判断，不询问 | 可加"列出候选让你确认" |
| L1 转换 | 只列素材（模式 B） | 可改自动展开（模式 A） |

---

## 三、成功标准

第一版跑两周后，检查：

| 指标 | 达标线 | 说明 |
|---|---|---|
| 日均记录条数 | 1–3 条 | 太多说明噪音大，太少说明检测太严 |
| 有效记录占比 | ≥ 60% | 翻一遍觉得"这个能写"的比例 |
| 提醒不觉得烦 | 主观 | 如果开始无视提醒，说明上限要调低 |
| 两周能凑出 | ≥ 1 篇 L2 | 验证素材池是否够用 |

**如果日均超过 5 条** → 检测太松，收紧细节判定标准
**如果一周不到 3 条** → 检测太严，或项目 focus 写窄了

---

## 四、使用预期

```
日常：你正常写代码，Skill 静默记录
      偶尔在回答末尾看到一行 📸 提醒
      你顺手截个图存到 .dev-log/shots/
      
两周后：打开 log.md 看一眼，可能已有 15-30 条
       说"生成博客草稿"，得到一篇初稿
       花 30-60 分钟补充 → 发布
```

**唯一新增动作**：截图存到固定文件夹，几秒钟。

---

## 五、已知的取舍

| 取舍 | 说明 |
|---|---|
| 可能漏记 | 检测偏严，宁漏勿滥 |
| 可能记了垃圾 | 事后手动删，比事后回忆省力 |
| 截图关联可能错 | 时间窗口 5 分钟，超出列孤儿让你认领 |
| 提醒可能错过 | 日志留占位，生成文章时再提示 |

这些都在可接受范围。**第一版的目标是跑通流程，不是完美。**

---

## 六、后续迭代方向（跑通后再考虑）

1. 根据漏记/滥记情况调整信号检测阈值
2. 加"手动标记"模式（对话中说"记一下这个"）
3. L1 自动展开（如果素材质量稳定）
4. 截图水印批量处理脚本
5. 跨项目聚合（全局项目清单）
6. 日志浏览器（本地可视化查看 log.md）
