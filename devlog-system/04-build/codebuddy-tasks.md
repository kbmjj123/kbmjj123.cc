# 04 · CodeBuddy 任务卡

> 逐个下发，一次一个。每个任务自带验收标准，完成后自查。
> 下发前让 CodeBuddy 先读：`README.md`、`01-skill/core-rules.md`、`04-build/mvp-scope.md`。

---

## T1 · 全局核心规则文件

**上下文**：`01-skill/core-rules.md`

**任务**：把核心规则写成 CodeBuddy 全局规则文件。

**注意**：
- 文件路径按你的 CodeBuddy 全局规则目录实际位置
- 若 CodeBuddy 规则文件需要特定 frontmatter 或语法，按它的要求调整
- 内容以 `core-rules.md` 为准

**验收**：
- [ ] 文件放到全局规则目录，CodeBuddy 能加载
- [ ] 包含全部十节内容
- [ ] 触发时机、记录格式、脱敏、截图提醒、禁止事项都在

---

## T2 · 信号检测逻辑细化

**上下文**：`01-skill/signal-detection.md`

**任务**：把五类信号的检测写成明确的判定规则（提示词形式）。

**验收**：
- [ ] 五类信号各有正反例
- [ ] 有明确的"太模糊则不记录"判定标准
- [ ] ignore 优先级最高
- [ ] 有"宁漏勿滥"的明确指令

---

## T3 · 记录格式与标签

**上下文**：`01-skill/record-format.md`

**任务**：定义日志条目的完整输出格式与标签提取规则。

**验收**：
- [ ] 格式严格对齐文档（含时间戳、六个字段）
- [ ] 标签 = 项目 tags + 技术标签，3–5 个
- [ ] 标题写法有公式约束
- [ ] append-only，明确禁止修改已有条目

---

## T4 · 截图提醒机制

**上下文**：`01-skill/screenshot.md`

**任务**：实现提醒分级、上限控制、时间戳关联。

**验收**：
- [ ] 必截 / 可选 / 不截 三级分类清晰
- [ ] 每日上限 3–5 次，超出静默
- [ ] 同一问题只提醒第一次
- [ ] 提醒格式是单行，不等待回复
- [ ] 未截图的条目留"建议配图（未捕获）"占位
- [ ] 5 分钟时间窗口关联逻辑

---

## T5 · 脱敏过滤

**上下文**：`01-skill/privacy-and-directory.md`

**任务**：定义脱敏规则，写入日志前执行。

**验收**：
- [ ] 四类敏感内容全部覆盖
- [ ] 策略是"直接丢弃"而非占位替换
- [ ] 拿不准时丢弃
- [ ] 提示 gitignore 配置

## T6 · 项目配置读取

**上下文**：`02-project/config-template.md`

**任务**：实现 `.dev-log/config.md` 的读取与合并逻辑。

**验收**：
- [ ] 配置文件不存在时用默认配置，不报错
- [ ] tags / focus 是追加语义
- [ ] ignore 是覆盖语义且优先级最高
- [ ] settings 覆盖全局默认值

## T7 · 聚合生成草稿

**上下文**：`03-aggregation/l2-articles.md`

**任务**：实现"生成博客草稿"指令的完整流程。

**验收**：
- [ ] 按标签分组，选关联度高的 3–5 条
- [ ] **先列出孤儿素材让用户认领**（未配图条目 + 未归属截图）
- [ ] 输出到 `.dev-log/drafts/YYYY-MM-DD-<主题>.md`
- [ ] 按问题类型分组，不按时间罗列
- [ ] 素材不足 3 条时不强行生成
- [ ] 询问是否标记 used

---

## T8 · 初始化脚本（可选）

**任务**：写一个小脚本，在新项目里一键初始化 `.dev-log/` 目录。

```bash
# 用法：./init-devlog.sh
mkdir -p .dev-log/{shots,outputs,drafts}
cp <模板路径>/config-template.md .dev-log/config.md
echo ".dev-log/" >> .gitignore
```

**验收**：
- [ ] 创建完整目录结构
- [ ] 复制配置模板
- [ ] 自动加 gitignore

---

## 全局约束（每次下发都要重复）

1. **不主动打断用户** —— 记录静默进行，判定不记录时零提示
2. **不修改已有日志** —— append-only
3. **拿不准就不记录 / 就拿不准就丢弃（脱敏）**
4. **截图提醒有上限** —— 不做噪音源
5. **不自动发布** —— 草稿必须用户过目
6. **不确定回来问** —— 不要自己假设业务规则

---

## 建议执行顺序

**最小可用（当天能用）**：T1 → T3 → T4 → T6

跑一周后，根据实际记录质量补 T2（调检测松紧）和 T7（聚合）。

T5（脱敏）虽然排第五，但**建议在 T3 时一并考虑**，
因为一旦日志里写入了敏感信息，后面清理很麻烦。
