# 07 · 文章原型：按素材类型决定结构

> **本文件取代 `01-content-strategy.md` 第五节的"内容公式"。**
> 那份六段公式已被废弃（见文末说明）。

---

## 一、为什么废弃固定公式

`01-content-strategy.md` 第五节的六段公式：

```
1. 我做了什么  2. 为什么做  3. 技术路径  4. 真实数据  5. 踩过的坑  6. 如果重做
```

它被严格套用后，19 篇文章长成了同一个八槽位表单：

| 槽位 | 出现次数 |
|---|---|
| `## TL;DR`（开头） | **19 / 19** |
| `## Lessons Learned`（结尾） | **16 / 19** |
| `## My Take` | 14 / 19 |
| `## Background` | 12 / 19 |
| `## Result` | 8 / 19 |

两个后果：

1. **模板化 = 可批量生成。** 格式一致性恰好是可自动化程度的代名词。
   这正是 `03-first-principles.md` 判定的"AI 已死"区域。
2. **TL;DR 在 AI Overview 时代是自伤。** 把结构化结论放在 H2，
   等于主动递给 AI Overview 一份可直接摘走的答案，点击归零。

**讽刺点**：那份公式的原话是"第 4、5 段是 AI 无法替代的部分"。
它想保护的东西，被它自己固定的格式破坏了。

### 替代原则

> **不是"没有格式"，是"先有素材，由素材决定结构"。**

这也正是"不按时间升级，按信号升级"的自然推论——
信号不只决定什么时候写，还决定写成什么样。

## 二、四个原型

### ① 踩坑排查型

**适用**：我遇到一个具体问题，排查并解决了。

| 槽位 | 内容 |
|---|---|
| 现象 | 具体报错原文 / 异常数据 |
| 我以为是 X | **保留错误的中间判断** |
| 实际是 Y | 真正的根因 |
| 怎么定位到的 | 诊断路径 |
| 解法 | 最终采用的方案 + 代价 |
| 什么情况下你会碰到 | 复现条件 |

**开头**：直接上现象。**不写 TL;DR**——结论放开头，读者就不看推理了，而推理才是他能复用的部分。

**结尾**：给"复现条件"，不是"我的教训"。

**禁忌**：不要省略中间的错误判断。那正是 AI 给不了的东西。

---

### ② 决策权衡型

**适用**：面对约束做了选型，能说清为什么选这个。

| 槽位 | 内容 |
|---|---|
| 我的约束是什么 | 时间/成本/能力/已有栈 |
| 候选方案 A / B / C | 各自优劣 |
| 我选了哪个 | 以及理由 |
| 代价是什么 | **必须写，没有代价的决策是假的** |
| 什么情况下你该选另一个 | 给读者的选择规则 |

**结尾**：必须是**读者的选择规则**，不是"我的教训"。这是它区别于复盘型的关键。

**禁忌**：不要写成"我选了 X，因为它最好"。没有代价的决策没有信息量。

---

### ③ 教程操作型

**适用**：教别人做成一件具体的事。

| 槽位 | 内容 |
|---|---|
| 你能得到什么 | 面向读者的收益 |
| 前置条件 | 版本、账号、依赖 |
| 分步操作 | 每步可验证 |
| 怎么验证成功了 | 明确的成功信号 |
| 常见失败 | 至少 2 条 |
| **我的真实数据** | **强制，见下** |

#### 强制附加项

教程型必须包含"只有你有的东西"，否则**降级为不值得写**：

- 真实账单 / 真实耗时
- 你踩过的坑（不是文档的注意事项）
- 运行 N 个月后的变化

> 纯步骤 = 已死（AI 五分钟能写）。
> 步骤 + 你的真实数据 + 你踩的坑 = 活着。

---

### ④ 复盘叙事型

**适用**：一段时间过去，有数据、有判断变化。

| 槽位 | 内容 |
|---|---|
| 时间线 | 关键节点 |
| 关键转折点 | 什么时候想法变了 |
| 数据 | 成本 / 流量 / 收入 / 性能 |
| 我的判断哪里变了 | **核心槽位** |

**这是 AI 最不可替代的一类。** 纵向时间、真实后果、判断变化，三者 AI 都没有。

**禁忌**：不要写成流水账。没有判断变化的时间线毫无价值。

---

## 三、TL;DR 的处理规则

| 方案 | 说明 |
|---|---|
| **默认不写** | 大多数文章不需要 |
| 长文可写 | > 2000 字才考虑 |
| **必须改写** | 从"结论摘要"改成"你会得到什么" |

### 关键区别

```
❌ TL;DR: D1 事务不支持跨 HTTP 请求，改用 batch API 即可。

✅ 读完之后你会知道：为什么 D1 的事务会在你以为没问题的地方静默失败，
   以及三种绕法各自的代价。
```

**"结论摘要"直接给答案；"你会得到什么"制造信息缺口。**

同样是开头一段话——前者喂养 AI Overview，后者留住读者。

但不能直接砍——umami 系列是站内 GSC 表现最好的之一（Part 1 首月 28 impressions，全站最高）。
适用上面第三型的强制附加项规则：补真实数据，而不是删掉。

## 五、存量改造顺序

**先改复盘叙事型那 4 篇。**

理由：这是 AI 最不可替代的一类，而现在被硬塞在八槽位通用模板里，损失最大。

教程型（umami 4 篇）暂缓：它们表现好，动了有风险，
而且它们的结构问题主要在开头 TL;DR，改那一处即可，不必改整体。

### 执行方式（不要批量改）

1. 先做 **2 篇**试点，标记改造日期
2. 一个月后拉 GSC 对比 impressions / clicks 变化
3. 有效果再推；没效果说明结构不是瓶颈，停下

**新文章一律用新结构**，从重启后第一篇开始。

---

## 六、关于旧公式

`01-content-strategy.md` 第五节的六段公式**不再作为文章结构使用**。

它作为"选题自检清单"仍有价值（提醒你别忘了写数据和踩坑），
但**不能当作骨架去填**。区别是：

- 骨架：先有模板，往里塞素材 → 19 篇雷同
- 清单：先有素材，写完后对照检查有没有漏 → 结构由素材决定
