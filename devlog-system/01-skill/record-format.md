# 01 · 记录格式规范

---

## 一、完整格式

```markdown
## [2026-10-17 14:32] Nuxt Image 模块 SSR 下 hydration 报错

- **场景**：给博客加图片优化，引入 @nuxt/image
- **问题**：SSR 下 `useImage` 返回 undefined，hydration mismatch
- **解决**：改用 `client-only` 包裹，避免服务端调用
- **决策**：没选 `lazy` 方案，因为 lazy 会导致 LCP 变差
- **标签**：#nuxt #image #ssr #踩坑 #repocheck
- **配图**：建议配图（未捕获）

---
```

---

## 二、字段说明

| 字段 | 必填 | 要求 |
|---|---|---|
| 时间戳 | ✅ | `YYYY-MM-DD HH:mm`，用于与截图关联 |
| 标题 | ✅ | 具体到能一眼看懂，15 字以内 |
| 场景 | ✅ | 一句话交代在做什么 |
| 问题 | ✅ | 保留关键报错原文，不要只写"报错了" |
| 解决 | ✅ | 最终采用的方案，不是尝试过的所有方案 |
| 决策 | 可选 | 有选型对比时才写，写清**为什么** |
| 标签 | ✅ | 3–5 个，见下方规则 |
| 配图 | ✅ | 三选一，见 `screenshot.md` |

---

## 三、标题写法

```
❌ 修复了一个 bug
❌ 图片问题
✅ Nuxt Image 模块 SSR 下 hydration 报错
✅ Cloudflare D1 事务不支持跨 HTTP 请求
✅ Tailwind purge 导致生产环境样式丢失
```

**公式**：`[什么东西] + [什么情况下] + [发生了什么]`

---

## 四、标签体系

### 构成

```
标签 = 项目 config.tags + 本次技术标签
```

### 项目 tags（自动附加）

来自 `.dev-log/config.md`，例如：
`[nuxt, cloudflare, vue]`

### 技术标签（从对话提取）

**优先使用的维度：**

| 维度 | 示例 |
|---|---|
| 框架 / 库 | `#nuxt` `#vue` `#tailwind` `#prisma` |
| 服务 / 平台 | `#cloudflare` `#vercel` `#d1` `#workers` |
| 问题类型 | `#ssr` `#hydration` `#部署` `#性能` `#类型` |
| 动作 | `#踩坑` `#迁移` `#优化` `#选型` |

### 规则

- 总数 3–5 个，不要堆砌
- 小写，多词用连字符（`#edge-runtime`）
- 项目 tags 优先保留，技术标签补足

---

## 五、日志文件的整体结构

```markdown
# Dev Log · repocheck

> 自动生成，追加模式。手动补充说明请用「> 补充：」前缀。

---

## [2026-10-17 14:32] Nuxt Image 模块 SSR 下 hydration 报错
...

---

## [2026-10-17 16:05] Cloudflare D1 事务限制
...

---
```

用 `---` 分隔每条记录，便于解析。

---

## 六、手动补充

你随时可以手动往日志里加内容，用统一前缀标明是人工补充：

```markdown
> 补充：这个问题后来在 v3.2 又出现了，原因是 xxx
```

**Skill 不会修改带「补充：」前缀的内容。**

---

## 七、已用条目的标记

生成草稿后，被使用的条目尾部追加：

```markdown
- **配图**：已捕获
<!-- used: 2026-10-20-d1-pitfalls.md -->
```

被标记的条目在下次聚合时默认跳过（除非用户要求包含）。

---

## 八、不修改原则

**日志是 append-only 的。**

| 允许 | 禁止 |
|---|---|
| 追加新条目 | 修改已有条目内容 |
| 追加「补充：」 | 删除条目 |
| 追加 used 标记 | 重排顺序 |

原始记录的价值在于真实，事后修改会破坏这个价值。
