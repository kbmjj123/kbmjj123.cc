# 01 · 截图捕获机制

> 文本日志 AI 能编，**截图 AI 编不出来**。
> 带真实报错截图和运行界面的文章，可信度是纯文字的三倍以上。

---

## 一、核心难题

截图是**你的一个动作**：你看到界面炸了 → 按截图键 → 存下来。
Agent 没法替你按这个键。

所以这块不能全自动，只能做到：
**极低成本的手动捕获 + 尽可能多的自动补位。**

---

## 二、三层捕获

### 第一层：全自动（Agent 自己做）

这些不用你管，规则触发即自动存：

- 命令报错时的**终端输出**（Agent 能看到，直接存到 `outputs/`）
- Playwright / E2E 测试失败时的**自动截图**（测试框架原生支持）
- 构建失败日志、npm audit 结果、性能指标数字
- 前后对比：改之前的报错 vs 改之后的成功输出

存到 `.dev-log/outputs/`，按时间戳命名。

### 第二层：半自动（Agent 提醒你截）

检测到"值得配图"时，在回答末尾附一行提醒。
你顺手截一下，成本几秒。

### 第三层：随手截（最重要）

界面效果、UI 改动、部署成功的页面、奇怪的渲染问题——
只有你知道什么时候值得拍。

设计目标：**让随手截的路径短到不能再短。**

```
截图 → 存到 .dev-log/shots/ → 完事
```

不用改名、不用整理、不用告诉 Agent。

---

## 三、提醒分级（防止噪音）

| 类型 | 例子 | 处理 |
|---|---|---|
| **必截** | UI 渲染错乱、布局崩了、页面白屏、奇怪视觉效果 | 立即提醒 |
| **必截** | 前后对比（改之前 vs 改之后） | 立即提醒 |
| **必截** | 阶段性成果（部署成功、功能跑通、界面完成） | 提醒 |
| **不截** | 纯终端报错（文本日志已自动存） | 不提醒 |
| **不截** | 代码逻辑报错（没有视觉载体） | 不提醒 |
| **可选** | 中间过程、调试状态 | 不提醒 |

### 判断标准一句话

> **这个东西"看起来"是什么样，是文字描述不清的吗？**
> 是 → 截；不是 → 文本够了。

---

## 四、提醒的形式

```
📸 值得截图：SSR 下页面 hydration 后布局错位 → 存到 .dev-log/shots/
```

要点：
- 一句话，说清**截什么**和**存哪**
- **不等你回复**，Agent 继续干活
- 截完也不用告诉它，靠时间戳自动关联

---

## 五、两个必须加的限制

### 1. 每日上限：3–5 次

超过就静默，只在日志里记一笔"建议配图（未捕获）"。
否则你第二天就会开始无视它。

### 2. 同一问题不重复提醒

同一个报错反反复复出现，只提醒第一次。

---

## 六、时间戳关联（核心机制）

你截了图，Agent 怎么知道它对应哪个问题？**靠时间对齐。**

```
14:32:10  Agent 记录一条日志：SSR hydration 报错
14:32:45  你在 shots/ 里存了一张截图
          → 时间差 35 秒 → 自动关联
```

### 规则

- 关联窗口：**5 分钟内**自动配对
- 一图对一条（时间最近的）
- 一条可对应多图（前后对比）

正常情况下你**完全无感**，只在少数时候需要手动干预。

---

## 七、提醒了但没截怎么办

必然会发生的——你忙着 debug，根本没看见提醒。

**Agent 在日志里留一个占位：**

```markdown
- **问题**：hydration 后布局错位
- **配图**：建议配图（未捕获）
```

生成文章时，所有"未捕获"的条目列出来：

> 这几处建议配图但没有，要不要补？还是文字描述就行？

你再决定补还是放弃。不会出现"文章写好了发现没图"的尴尬。

---

## 八、孤儿素材回收

**定义：**
- 截了图但对不上任何日志（时间超出窗口）
- 日志标了"建议配图"但没有图

**处理方式：**

生成文章草稿时，先把所有孤儿素材列出来让你认领：

```
以下素材还没归属，要不要用？
1. shots/2026-10-17-143245.png —— 猜是 SSR 报错截图？
2. shots/2026-10-17-160812.png —— 猜是部署成功页面？
```

你点一下就归位。比事后翻文件夹找图省力太多。

---

## 九、目录结构

```
.dev-log/
├── log.md              # 主日志（自动追加）
├── shots/              # 截图（你随手丢进来）
│   ├── 2026-10-17-143245.png
│   └── 2026-10-17-160812.png
├── outputs/            # 自动捕获的文本输出
│   ├── 2026-10-17-143210-error.txt
│   └── 2026-10-17-150120-build.txt
└── drafts/             # 生成的文章草稿
```

**命名全部靠时间戳，不要求你起名字。**

---

## 十、给截图加水印（建议）

如果你打算公开发布，建议在发布前给截图加半透明站点水印：

- 防盗图
- 图片被转载时自动带来源

这一步放在生成草稿后、发布前，手动或脚本批量处理均可。
