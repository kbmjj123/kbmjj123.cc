# 01 · 隐私脱敏与目录结构

---

## 一、脱敏规则（强制）

写入日志前必须过滤以下内容：

| 类别 | 示例 |
|---|---|
| 密钥 | API key、token、password、secret、私钥 |
| 连接信息 | 数据库连接串、内网 IP、SSH 配置 |
| 业务数据 | 用户数据、订单信息、内部业务逻辑细节 |
| 配置文件 | `.env` 内容、任何含凭证的配置 |

### 处理方式

```
发现敏感内容 → 直接丢弃该片段，不做占位替换
```

**宁可少记，不可泄密。拿不准的内容直接丢弃。**

### 日志文件必须 gitignore

```gitignore
# .gitignore
.dev-log/
```

日志不提交到任何仓库。

---

## 二、目录结构（项目内）

```
<项目根目录>/
└── .dev-log/
    ├── config.md        # 项目配置（唯一需要你手写的）
    ├── log.md           # 主日志（Skill 自动追加）
    ├── shots/           # 截图（你随手丢进来）
    ├── outputs/         # 自动捕获的文本输出
    ├── drafts/          # 生成的文章草稿
    └── archive/         # 归档（日志超 50 条时自动移入）
```

### 为什么存项目内

| 优点 | 说明 |
|---|---|
| 上下文清晰 | 多项目并行不串味 |
| 截图天然对应 | 不用判断截图属于哪个项目 |
| 跟着项目走 | 项目归档时日志一起走 |

跨项目聚合靠**全局维护项目路径清单**，聚合时按需扫描，
不依赖物理位置统一。

---

## 三、全局路径清单

跨项目聚合时，在聚合指令里指定项目路径即可：

```
整理一下 ~/proj-a 和 ~/proj-b 最近关于 cloudflare 的记录
```

或维护一个全局清单文件（可选）：

```markdown
# ~/.dev-log-projects.md
- repocheck: ~/code/repocheck
- blog: ~/code/my-blog
- tool-x: ~/code/tool-x
```

第一版可先手动指定路径，跑通后再考虑自动扫描。

---

## 四、文件命名规则

| 类型 | 命名 | 说明 |
|---|---|---|
| 截图 | `YYYY-MM-DD-HHmmss.png` | 你存的时候不用改名，Skill 或脚本批量重命名 |
| 输出 | `YYYY-MM-DD-HHmmss-<类型>.txt` | 类型：error / build / test / audit |
| 草稿 | `YYYY-MM-DD-<主题>.md` | 主题用英文短横线 |

**核心：靠时间戳，不靠人起名。**

---

## 五、日志归档规则

日志超过 50 条时：

1. 已标记 `used` 的条目移到 `archive/log-<YYYY-MM>.md`
2. 主日志保留未使用的条目
3. 归档文件永久保留，聚合时可按需包含

避免单文件过大影响读取速度。

---

## 六、gitignore 建议

```gitignore
# 整个目录不入库
.dev-log/

# 如果只想忽略截图和输出，保留日志：
# .dev-log/shots/
# .dev-log/outputs/
```

**建议整个目录忽略** —— 日志里可能有你没注意到的敏感片段。
