# 00 · 两阶段路线：从博客到工具专区

> 这是 DevLog System 的最终用途：为第二阶段的工具专区积累原材料。
> 但**现在不要开专区**——先写博客攒权重。

---

## 一、整体路径

```
阶段一（现在 – 6~9 个月）
  只写博客，目标：30+ 篇、DR ≥ 20、GSC 有数据
  同时 DevLog System 自动积累工具使用清单
        ↓
阶段二（权重达标后）
  开 /tools 专区 + /submit 入口
  开放外链申请，按「我愿意用」标准审核
        ↓
阶段三
  给被收录者推 Badge，看回流数据
```

---

## 二、为什么必须分阶段

工具专区（curated directory）的价值**完全取决于域名权重**：

- 挂在 DR 10 的站上 → 没人愿意来提交
- 挂在 DR 35 的站上 → 别人主动找你

**提前开只是浪费一个入口位**，还会引来一堆垃圾提交和推销邮件。

### 可判定的开站阈值

别用"感觉差不多了"，看这四个指标，**满足三个再开**：

| 指标 | 阈值 | 怎么查 |
|---|---|---|
| 域名权重 | DR ≥ 20 | Ahrefs 免费版 / Moz |
| 收录页数 | ≥ 30 页被 Google 收录 | `site:你的域名` |
| 自然搜索月点击 | ≥ 300 | Google Search Console |
| 长尾词进前 10 | ≥ 5 个 | GSC 查询报表 |

按英文技术博客正常节奏，认真写大概 **6–9 个月**能到这个线。

---

## 三、模式修正：不是"卖外链"，是"精选目录"

**重要**：这不是付费外链生意（Link Insertion / Niche Edits），
性质完全不同，风险也完全不同。

| | 卖外链 | 精选目录 |
|---|---|---|
| 谁付钱 | 对方付钱买位 | 免费，编辑选择 |
| 审核 | 来者不拒 | 严格筛选 |
| 风险 | 违反 Google link scheme | 正常编辑行为 |
| 收益 | 短期现金 | 内容 + 外链回流 |

### 飞轮

```
别人提交 → 你审核收录 → 给他一个 "Featured on XXX" Badge
                                    ↓
                        他把 Badge 挂进自己 README
                                    ↓
              他的用户点 Badge → 回到你的专区 → 看到其他工具
```

**每一方都拿到想要的东西：**
- 提交者：曝光 + 第三方背书
- 你：免费内容素材 + 持续外链回流
- 读者：经过筛选的清单

你的投入只是**审核的十分钟**，不是七小时的测评。

---

## 四、唯一的致命坑：别做成链接农场

如果一个专区只是"工具名 + 一句话 + 链接"的罗列，
在 Google 眼里就是低质量目录页，不仅没排名，还会拉低整站。

**区分点在于编辑价值**——每个收录项必须有你自己的判断。

```markdown
❌ Nuxt Auth — 一个 Nuxt 鉴权模块。链接：xxx

✅ Nuxt Auth — Nuxt 生态最常用的鉴权模块。
   适合：需要开箱即用 session 管理的项目。
   注意：SSR 下 session 初始化会 hydration mismatch，需 client-only 包裹。
   （我在真实项目里用过，踩过这个坑）
```

后面这种，AI 生成不出来，也不构成垃圾目录。
**你的编辑判断本身就是内容。**

---

## 五、收录等级（复用之前的分级设计）

| 等级 | 含义 | 判定成本 | Badge |
|---|---|---|---|
| **Listed** | 收录，相关且质量过关，但没深度用过 | 5 分钟审核 | 灰色 |
| **Used** | 真实项目里用过，能说清适合什么场景 | 已有经验，0 成本 | 蓝色 |
| **Tested** | 跑过完整验证，有证据（自愿才做） | 不做也行 | 绿色 |

**默认只给 Listed 和 Used。** Tested 不是必选项，
是你有空有兴趣时才做的升级 —— 这样不存在"每周七小时"的压力。

---

## 六、审核标准（必须公开写死）

在 `/tools` 或 `/submit` 页面写明：

- 必须和前端 / 全栈 / 开发工具相关
- 必须真的能用（不是 demo 都跑不通的半成品）
- 不接受"付钱就上"
- 保留无条件下架权

**别承诺"提交必收录"。** 公开写明"通过率不高"，反而提高专区含金量，
也让被收录者更愿意去挂 Badge。

---

## 七、合规边界

现在是**免费收录 + 编辑选择 + 主题相关** → 用 dofollow 完全正常，
这是普通编辑行为，不涉及违规。

**但将来如果要收费**（对方付费请你写），性质就变了，必须：
- 加 `rel="sponsored"` 或显著标注赞助
- 公开赞助政策页

**建议现阶段写死"不收费"，只做编辑选择。** 最干净，也最保护站点。
将来要变现，优先考虑赞助内容位（标注的那种），而不是卖裸链接。

---

## 八、等待期可以零成本埋的三件事

这三件都不额外花时间，写文章时顺手带上，将来第二阶段直接接得上：

**1. 选题往"工具 / 生态"靠**
优先写"我用过什么工具、怎么选的、踩了什么坑"。
将来开专区时，这些文章天然是专区的流量入口和内链池。

**2. 每篇文章留一个自然的"相关工具"位置**
不是现在加链接，是格式上预留一个小节。
将来收录某工具时直接挂上去，外链出现在内容语境里，
比孤零零的目录页健康得多。

**3. 攒自己的使用清单**
平时用过的库随手记一句：什么场景用的、好不好用、有没有坑。
**这是第二阶段最值钱的原材料 —— 你已经有的经验是零成本的。**

---

## 九、专区的第一批内容从哪来

**不要用别人提交的。用你自己清单里的。**

这样专区一开就有质量，不是空壳 —— 空壳目录页对 SEO 是负分。

而这批内容，正是 DevLog System 在阶段一自动积累的：
写 30 篇项目记录 → 用到上百个库 → 每个都有一两句真实判断。
